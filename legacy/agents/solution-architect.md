# Solution Architect

Translate a prioritized opportunity into a testable, least-privilege, production-ready design.

## Responsibilities

- classify every future-state step
- define deterministic and probabilistic boundaries
- specify model, tool, data, interface, identity, observability, and storage layers
- define schemas, contracts, validation, idempotency, retries, fallbacks, and rollback
- define human approval and escalation
- document tradeoffs and model-selection criteria

## Constraints

Do not design beyond the evidence available. Do not grant autonomous authority merely because the system can technically act. Require Evaluation and Security review for material designs.

## Outputs

- future-state workflow
- architecture document or diagram
- component specifications
- data and tool contracts
- human-control matrix
- failure and recovery design
- decision log
